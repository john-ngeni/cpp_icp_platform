# Bundle Holder Integration Architecture

## Overview

Bundle holders can integrate into the overall CPP PWA by publishing content to their ENS subdomains following CPP standards. This content gets incorporated into the PWA on the next version update.

## Domain Architecture

### **Primary Structure**
- **Public Site**: `coolplanet-foundation.org` (Next.js, SEO-optimized)
- **Member Platform**: `members.coolplanet-foundation.org` (React + Azle, unified experience)
- **ENS Mirror**: `cpf.nft` mirrors `coolplanet-foundation.org` (ICANN independence)

### **NFT Model Qualification**
- **CPP1**: `cpp1.members.coolplanet-foundation.org`
- **CPP2**: `cpp2.members.coolplanet-foundation.org`
- **Future Models**: `cpp{n}.members.coolplanet-foundation.org`

### **Bundle Holder Subdomains**
- **ENS Structure**: `bundle-holder.cpp1.cpf.nft`
- **DNS Structure**: `bundle-holder.cpp1.members.coolplanet-foundation.org`
- **Integration**: Content published to ENS gets incorporated into PWA
- **Control**: Smart contract gives ENS subdomain control to wallet holder
- **Challenge**: Need to associate external wallet addresses with Internet Identity

## Wallet Association and ENS Control

### **Challenge: External Wallet Control**
The smart contract gives ENS subdomain control to the wallet holder, which may be:
- **External Ethereum/Polygon address** (non-IC generated)
- **IC-generated address** (via chain-key cryptography)
- **Hybrid approach** (IC manages external addresses)

### **Internet Identity Association Options**

#### **Option 1: IC Chain-Key Cryptography**
```typescript
// IC generates and manages Ethereum/Polygon addresses
interface ChainKeyWallet {
  ii_principal: string;
  ethereum_address: string; // Generated by IC chain-key
  polygon_address: string;  // Generated by IC chain-key
  ens_control: boolean;     // IC controls ENS subdomain
}

// Benefits: Seamless II integration, no external wallet needed
// Challenges: IC dependency, potential vendor lock-in
```

#### **Option 2: External Wallet Association**
```typescript
// User provides external wallet address
interface ExternalWalletAssociation {
  ii_principal: string;
  external_address: string; // User's existing wallet
  association_proof: string; // Cryptographic proof of ownership
  ens_control: boolean;     // External wallet controls ENS
}

// Benefits: User autonomy, existing wallet compatibility
// Challenges: Association complexity, security considerations
```

#### **Option 3: Hybrid Approach**
```typescript
// IC manages external addresses on user's behalf
interface HybridWallet {
  ii_principal: string;
  ic_managed_address: string; // IC-generated but external
  user_delegation: boolean;   // User delegates control to IC
  ens_control: boolean;       // IC controls ENS via delegation
}

// Benefits: Best of both worlds, user choice
// Challenges: Complex delegation mechanisms
```

### **Recommended Approach: External Wallet Association**

#### **Association Process**
1. **User provides external wallet address** during II setup
2. **Cryptographic proof of ownership** (sign message with external wallet)
3. **Association stored in IC** with user's II principal
4. **ENS subdomain control** remains with external wallet
5. **PWA acts as bridge** between II and external wallet operations

#### **Implementation**
```typescript
// Association verification
async function verifyWalletOwnership(
  ii_principal: string,
  external_address: string,
  signature: string,
  message: string
): Promise<boolean> {
  // Verify signature matches external address
  const isValidSignature = await verifySignature(
    external_address,
    signature,
    message
  );
  
  if (isValidSignature) {
    // Store association in IC
    await storeWalletAssociation({
      ii_principal,
      external_address,
      association_date: Date.now()
    });
    return true;
  }
  
  return false;
}

// ENS operations through PWA
async function publishToENS(
  ii_principal: string,
  ens_subdomain: string,
  content_hash: string
): Promise<boolean> {
  // Get associated external wallet
  const wallet_association = await getWalletAssociation(ii_principal);
  
  if (!wallet_association) {
    throw new Error("No external wallet associated with II principal");
  }
  
  // PWA acts as bridge to external wallet
  return await publishViaExternalWallet(
    wallet_association.external_address,
    ens_subdomain,
    content_hash
  );
}
```

## Integration Mechanism

### **Publishing Process**

1. **Bundle Holder Associates Wallet with II**
   ```typescript
   // User signs message with external wallet to prove ownership
   const message = `Associate wallet ${external_address} with II principal ${ii_principal}`;
   const signature = await signMessage(external_wallet, message);
   
   // Verify and store association in IC
   await verifyWalletOwnership(ii_principal, external_address, signature, message);
   ```

2. **Bundle Holder Publishes to ENS via PWA**
   ```typescript
   // PWA acts as bridge between II and external wallet
   const content_hash = await ipfs.add(bundle_holder_content);
   
   // PWA uses associated external wallet to publish to ENS
   await publishToENS(ii_principal, ens_subdomain, content_hash);
   ```

2. **CPP PWA Discovers Content**
   ```typescript
   // PWA periodically scans for new bundle holder content
   async function discoverBundleHolderContent() {
     const bundleHolders = await getBundleHolders();
     
     for (const holder of bundleHolders) {
       const ensContent = await resolveENS(holder.ens_subdomain);
       const metadata = await fetchMetadata(ensContent);
       
       if (isValidCPPContent(metadata)) {
         await queueForIntegration(metadata);
       }
     }
   }
   ```

3. **Content Validation**
   ```typescript
   function isValidCPPContent(metadata: BundleHolderMetadata): boolean {
     return (
       metadata.cpp_standard_version &&
       metadata.bundle_holder.did &&
       metadata.content.type &&
       metadata.content.visibility
     );
   }
   ```

4. **PWA Integration**
   ```typescript
   // Content gets incorporated into PWA on next version
   async function integrateBundleHolderContent(metadata: BundleHolderMetadata) {
     const content = await fetchContent(metadata);
     
     // Add to PWA content registry
     await addToContentRegistry({
       type: 'bundle-holder',
       source: metadata.bundle_holder.ens_subdomain,
       content: content,
       metadata: metadata
     });
     
     // Update navigation and search
     await updatePWAIndex(metadata);
   }
   ```

### **Content Discovery and Caching**

#### **Discovery Strategy**
- **Periodic Scanning**: PWA scans ENS subdomains every 24 hours
- **Event-Driven**: Bundle holders can trigger immediate discovery
- **Manual Approval**: Optional manual review before integration

#### **Caching Strategy**
- **IPFS Caching**: Content cached on IPFS for performance
- **Version Control**: Track content versions for updates
- **Fallback**: DNS fallback if ENS resolution fails

async function searchBundleHolderContent(query: string) {
  const results = await searchContentRegistry({
    type: 'bundle-holder',
    query: query,
    visibility: ['public', 'members']
  });
  
  return results.map(result => ({
    title: result.metadata.content.title,

## Security and Validation

### **Content Validation**
- **DID Verification**: Verify bundle holder owns the ENS subdomain
- **Wallet Association Verification**: Verify II principal has associated external wallet
- **Content Sanitization**: Sanitize HTML and prevent XSS
- **File Size Limits**: Prevent abuse with reasonable limits
- **Rate Limiting**: Limit publishing frequency

### **Wallet Association Security**
- **Cryptographic Proof**: Require signature from external wallet for association
- **Association Expiry**: Optional time-limited associations for security
- **Revocation Mechanism**: Allow users to revoke wallet associations
- **Audit Trail**: Track all wallet association and ENS operations

### **Access Control**
- **Visibility Levels**: Public, members-only, bundle-holders-only
- **II Authentication**: Required for publishing
- **Content Moderation**: Optional manual review process
